# Linva 视觉检测子代理规则（vision delegate）

## 触发条件（何时委派）

需要分析**图片内容**且满足任一条：

1. 父会话看不到图——读图返回占位（`[image/png]`）却无法描述，或用户消息内嵌图片报"无法处理"；
2. 图片多 / 大 / 需精读（截图走查、逐元素对比、图表读数、图内文字 OCR 类），精读会挤占父上下文；
3. 需要客观盲测式描述——父会话已持有预期答案，自己看图易被上下文污染。

不委派的反例：只确认文件是图片、取尺寸/哈希/格式元数据（`file` / `sips` 一次 bash 搞定）。

## 启动方式（按优先级）

### 1. 主通道：`task` 工具 + `delegate` 子代理（本机实测可用）

- `delegate` 继承父会话模型 `ark/glm-5.3-flash`（多模态），子代理用 `read` 读图片路径即得内联图像。
- 调用形状：

```
task(tasks=[{ agent: "delegate", task: "<图片绝对路径> + <具体问题清单> + <输出格式>" }])
```

### 2. 专用通道：`xd://subagent` + `vision-inspector`

- 项目代理定义：`.agents/agents/vision-inspector.md`（模型钉死 `ark/glm-5.3-flash`，只读工具 `read/grep/find/ls`，`defaultContext: fresh`）。
- 用 `xd://subagent` 的 `action: "list"` 可确认其被发现。
- **前提：`pi` CLI 可用**（PATH 有 `pi`，或设了 `PI_SUBAGENT_PI_BINARY`）。当前本机缺 `pi` CLI，此通道暂不可用；装好即用，无需改本规则。

### 3. 兜底：父会话直接 `read` 图片

- 当前主模型经 `read` 通道实测能看图（2026-10-01 盲测一致）。简单快速看一眼可先走此路；一旦失败或描述不可靠，立即转通道 1。

## 任务提示模板（防幻觉，必填项）

子代理任务必须包含：

- 图片**绝对路径**（一张或多张）；
- 要回答的**具体问题清单**（逐条编号）；
- 明示约束：「只报告实际可见内容，禁止凭文件名 / 上下文猜测；看不到就回答 `CANNOT_SEE: <原因>`」；
- 结构化输出格式（逐图 `## <路径>` + 要点）。

**禁止**把预期答案写进任务描述（污染盲测；`task` 的 `context` 字段同样不得泄露预期内容）。

## 证据红线

- 视觉结论必须来自子代理真实读图（`read` 返回内联图像），不得从路径 / 文件名 / 会话上下文推断。
- 关键判定（如 UI 走查结论）应让子代理**额外报告任务未提及的可见元素**，作为真实性交叉验证。

## 验证记录（2026-10-01）

- 盲测：240px PNG（绿底 / 红圆 / 底部蓝条 + 提示中未提及的白色方块），`delegate` 子代理全部命中，含「白方块右半叠压红圆左缘」的层叠细节——真实视觉，非上下文复述。
- `vision-inspector` 已被 `xd://subagent` `action: "list"` 发现（Model: ark/glm-5.3-flash）；启动受阻仅因缺 `pi` CLI。
- 原生 `task` 工具的代理发现是启动时快照，**不认**运行中新增的项目代理定义（`vision-inspector` 在 task 工具里不可见）——所以通道 1 用 `delegate`，不用自定义名。
