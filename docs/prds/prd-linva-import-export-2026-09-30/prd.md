# PRD：Linva — 迁移闭环（导入 + 自动保存 / 崩溃恢复）

## 0. 文档目的

本文描述把 Linva 从「能画图」打磨到「能正经用」的增量：**旧图进得来（导入）、崩溃不白干（自动保存 + 恢复）**。导出保持 Markdown / PNG 两入口并列（PDF 已移除）。

- **上游：** [v1 PRD](../prd-linva-2026-09-24/prd.md)；[导出 PRD](../prd-linva-export-2026-09-25/prd.md)（本增量复用其「全展开导出」「标题层级 MD」语义）
- **需求真源：** [机会卡片](../../pm/opportunities/2026-09-30-迁移闭环导入导出.md)（FR 编号 I1/I2/S1/S2 与卡片一致，下游引用稳定）
- **体验真源：** `prototype/import-export.html`（导入 / 导出 / 崩溃恢复 三个标签）
- **明确不在本增量：** XMind 格式导入（v1.1）、SVG 导出、PDF 导出、打印排版引擎、iCloud / 多文档、AI、大纲视图。**商业化（定价 / 付费 / 内购 / 账号）本版不做**（产品本人 2026-09-30 拍板）。

文档语言：中文优先。

---

## 1. 愿景与要完成的工作

用户已有存量导图（XMind / Markdown 大纲），Linva 目前只能自产自销 `.linva`，成果只有 Markdown/PNG 两种出口，且崩溃会丢「上次保存以来」的进度。本增量一次补齐两条链路：

- **导入（进得来）：** Markdown 大纲为第一路径，OPML / FreeMind 顺带；文件 → 导入 →（格式）→ 新文档。
- **防丢（不白费）：** 脏后防抖自动保存临时副本；崩溃后下次启动提示恢复，一键找回。

成功标准（SM 见 §7）：阿哲能把旧图搬进来、把图交付出去、且再也不怕崩溃丢进度。

## 2. 关键用户旅程

**UJ-I1. 阿哲把一篇 Markdown 大纲变成 Linva 导图。**

1. 文件 → 导入 → Markdown…，选中 `roadmap.md`；2. 预览确认解析出的树（根 = 首个标题，`#`→一级…，列表项为子节点）；3. 确认导入，画布呈现新文档，可继续编辑。

**UJ-S1. 阿哲崩溃后找回未保存的工作。**

1. 上次崩溃前改过图未保存；2. 下次启动出现横幅「检测到上次未保存的更改」+ 文档名 / 时间 / 修改数；3. 点「恢复更改」→ 内容回到崩溃前草稿，标记为未保存可继续编辑；也可以「忽略（丢弃草稿）」。

## 3. 术语表（增量）

| 术语 | 定义 |
|------|------|
| **导入** | 把外部格式（Markdown / OPML / FreeMind）解析为新的 `MindMapDocument` 并载入为当前文档；不改动磁盘上既有 `.linva`。 |
| **标题层级（导入）** | Markdown 中 `#`–`######` 标题映射为树的层级；首个标题为根，后续标题为对应层级节点。 |
| **列表项（导入）** | Markdown 无序列表 `-` / `*` / `•` 条目；连续列表项互为同级，挂在最近一个标题节点之下。 |
| **全展开导出** | 导出前临时清空全部 `collapsed`（复用导出 PRD FR-E3 语义），导出后恢复；画布折叠态不变。 |
| **折叠枝** | 处于折叠状态、画布上不可见的子树；全展开导出时仍完整包含。 |
| **临时副本** | 自动保存写入的草稿文件（应用支持目录下 `Unsaved/`），非正式 `.linva` 文档。 |
| **恢复草稿** | 启动时检测到临时副本后，提示用户恢复 / 忽略的草稿内容。 |
| **逻辑树** | 与显示无关的完整树：导入 / 导出均以逻辑树为准，折叠只影响画布显示与布局。 |

## 4. 功能需求

### 4.1 导入（进得来）

**描述：** 文件 → 导入 → 子菜单（Markdown… / OPML… / FreeMind…）。解析为**新文档**载入（等同「打开」语义，不并入当前文档）；解析纯函数可单测；任一格式失败给出可读错误，不崩溃、不改当前文档。实现 UJ-I1。

**功能需求：**

#### FR-I1：导入 Markdown

用户可通过「文件 → 导入 → Markdown…」把一个 `.md` 文件转换为新的导图文档。

**Consequences（可测）：**
- 首个标题成为根节点；`#`→深度 1，`##`→深度 2，依此类推（深度 7+ 收敛为深度 6 的子树最深点）。
- 字号标题与无序列表混排时：列表项挂在最近一个标题节点之下，连续列表项互为同级。
- 多行文案压为单行；空文案节点用「未命名」；空行 / 非标题非列表行忽略；非法格式（无任何标题）报「未识别为导图大纲」并中止导入。
- 导入不修改磁盘上任何既有 `.linva`。

**Out of Scope：** 有序列表（`1.`）、代码块 / 引用 / 图片、列表多级缩进（缩进层级 = v1.1）、Markdown 双向（导出已有）。

#### FR-I2：导入 OPML / FreeMind

用户可通过「文件 → 导入」分别选择 `.opml` 或 `.mm`（FreeMind）文件转换为新导图文档；与 FR-I1 共用同一「导入为新文档」流程与错误处理。

**Consequences（可测）：**
- OPML：`outline` 层级结构 → 树；`text` 为空时用「未命名」；`_note` / 其它属性忽略。
- FreeMind：`node` 嵌套结构 → 树；`TEXT` 为空时用「未命名」。
- 非法 XML / 空树：报可读错误并中止，不改当前文档。

**Out of Scope：** OPML 富文本 / 属性映射、FreeMind 坐标 / 图标 / 富文本属性。

### 4.3 自动保存 + 崩溃恢复（不白费）

**描述：** 用户改动文档后，系统在防抖窗口内写**临时副本**；正常保存后清理副本；下次启动若检测到未保存副本，显示恢复横幅。实现 UJ-S1。

**功能需求：**

#### FR-S1：自动保存

文档变脏后，系统在 2 秒防抖内把当前内存文档写入应用支持目录的临时副本。

**Consequences（可测）：**
- 从「变脏」到「副本落盘」的典型时延 ≤ 3s（含防抖）；只对已加载文档生效，不创建空副本。
- 「保存 / 另存为」成功后清除对应临时副本；退出前正常保存同样清除。
- 临时副本写入失败（磁盘满等）：静默降级并保留内存文档，不打扰编辑；下次启动不误报恢复。
- 临时副本不通过命令栈（非用户操作），不被 Undo 影响。

**Out of Scope：** 版本历史 / 多版本快照、iCloud 与多设备同步、跨会话窗口恢复。

#### FR-S2：崩溃恢复

启动时若检测到存在未保存的临时副本，显示恢复横幅：「检测到上次未保存的更改」+ 文档名 / 最近自动保存时间 / 修改内容摘要（如「N 处修改未写盘」），提供「恢复更改」与「忽略（丢弃草稿）」。

**Consequences（可测）：**
- 「恢复更改」：载入副本为当前文档，标记为未保存（title 栏带编辑点），可继续编辑并正常保存。
- 「忽略」：删除该副本，载入最近一次正式保存版本。
- 副本与正式文档配对通过「原文件 URL + 文档 ID」判定；无正式文件的未命名文档也支持恢复。
- 多副本（多次崩溃残留）只提示最新一份，其余按保留策略清理（见 §8 开放问题）。

### 4.4 分层与兼容（跨特性约束）

**描述：** 本增量不得破坏既有分层纪律与文件格式。

**功能需求：**

#### FR-C1：层边界不变

所有导入解析为 Model 层纯函数（仅 Foundation）；自动保存 / 恢复属 Session 层会话态（不入 `.linva`、不入命令栈）。

**Consequences（可测）：**
- `scripts/check-boundaries.sh` 构建期校验仍然全绿，白名单无新增 import。
- `LinvaCodec.currentVersion` 保持 2，不新增 `Node` 字段，老文件依旧可开。

## 5. 非目标（明确不做）

- XMind 格式导入（.xmind，v1.1）；SVG 导出；打印排版引擎（纸张 / 边距 / 页眉页脚精调）。
- iCloud / 多文档 / 文件库 / 版本历史。
- AI 集成（MCP / 生成 / BYOK）；大纲视图；富文本；关联线；多布局。
- **商业化**：定价 / 付费 / 内购 / 账号体系本版不做（另行立项，定价类调研线索存档备用）。

## 6. 验收要点

| # | 场景 | 期望 |
|---|------|------|
| 1 | 导入含标题 + 列表的 Markdown | 树结构与层级正确（根=首标题，列表挂最近标题下） |
| 2 | 导入含空行 / 空文案 / 非法输入的 Markdown | 不崩溃；空文案「未命名」；无标题报可读错误并中止 |
| 3 | 导入 OPML / FreeMind | 层级正确；非法 XML 报错中止；当前文档不受影响 |
| 4 | 自动保存 | 变脏后 ≤3s 副盘落盘；正常保存后副本清除 |
| 5 | 崩溃恢复 | 启动横幅 → 恢复后内容=草稿且标记未保存；忽略后草稿删除 |
| 6 | 分层 / 格式 | `check-boundaries.sh` 绿；`currentVersion` 仍为 2 |

## 8. 原生实现备注

- **Markdown 导入**：Model 层新增纯函数解析器（与 `MarkdownExporter` 对称：导出先序→标题，导入标题→树，同一定义互为逆）；单测覆盖。
- **OPML / FreeMind 导入**：`XMLParser`（Foundation）→ 树；仅取结构字段。
- **自动保存 / 恢复**：Session 层 `dirtyRevision` 防抖 + `Application Support/Unsaved/`；副本文件 = 文档 JSON + 元信息（原 URL、文档 ID、时间）；启动扫描在 `DocumentWorkflow` 入口。
- **命名**：`ExportNaming.safeFilename` 复用；导入格式注册表便于日后加 XMind。
- **测试**：导入解析（Model，纯函数）+ 恢复流程（Session）；沿用既有命名与目录约定。

## 9. 开放问题

1. **导入的撤销语义**：`[ASSUMPTION: 导入 = 载入新文档，Undo 栈重置]`；原型展示「确认导入（可撤销）」——若要 ⌘Z 回到导入前文档，需文档级快照 Undo，实现成本高，暂缓（v1.1 评估）。
2. **恢复副本保留策略**：多副本只留最新；正常保存清理；未命名文档副本保留时长（如 7 天）待实现时定。
