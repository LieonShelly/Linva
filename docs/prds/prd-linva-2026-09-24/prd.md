# PRD：Linva

*工作标题已确认：Linva。*

## 0. 文档目的

本文档面向产品本人与后续实现 Agent / 协作开发者，作为 **v1（可证明方向的 Mac 原生思维导图工具）** 的需求真源。结构遵循 BMAD Essential Spine：愿景 → 用户与旅程 → 术语表 → 功能与 FR → 非目标 → MVP 范围 → 成功指标 → 开放问题。

**输入依据：**

- 可交互原型：`prototype/index.html`、`prototype/app.js`、`prototype/styles.css`
- 已拍板方向：单窗口；中心辐射布局；Mac 优先；SwiftUI 壳 + Metal 画布（技术选型细节见同目录 `addendum.md`，本文不展开实现）

**文档语言：** 中文优先（见 `.agents/AGENTS.md`）。

---

## 1. 愿景

Linva 是一款运行在 **macOS** 上的思维导图工具，帮助用户把想法铺成「以中心主题向外辐射」的树状结构，并在无限画布上快速增删、编辑、折叠与浏览。

v1 的目标不是取代 XMind 等成熟产品的全功能，而是交付一个 **体验完整、方向可证伪** 的最小产品：用户打开窗口就能围绕中心主题组织思路，交互与布局与已认可的 HTML 原型一致，且主链路足够顺滑，值得继续做多文档、主题与导出等扩展。

它存在的意义：把「脑中一团」变成「看得见、改得动、缩得开」的结构；并同时验证「树模型 + 中心辐射布局 + 高性能画布」这一产品与技术方向是否成立。

## 2. 目标用户

### 2.1 要完成的工作（Jobs To Be Done）

- **功能：** 在头脑风暴或整理思路时，快速建立中心主题与多级分支，看清结构关系。
- **功能：** 在大图上平移、缩放、折叠，而不迷失焦点。
- **情感：** 感到「工具跟得上手速」，少为布局和操作分心。
- **情境：** 主要在 Mac 桌面、本地单机使用；第一版为自己 / 早期试用者服务。  
  `[ASSUMPTION: v1 的主要用户即产品构建者本人与少量受邀试用者，暂不以公开上架为成功门槛。]`

### 2.2 非用户（v1）

- 需要强协同编辑、云同步的团队
- 需要复杂演示 / 大纲双视图 / 多种版式模板的交付型用户
- iPhone / iPad 用户（平台后续再议）
- 需要企业权限、账号体系的组织买家

### 2.3 关键用户旅程

**UJ-1. 阿哲打开 Linva，把一次头脑风暴铺成中心辐射图。**

- **人物与情境：** 阿哲，独立开发者，刚开完需求讨论会，想马上把议题结构化。
- **进入状态：** 启动 App，看到单窗口：顶栏工具条 + 中央画布；默认存在一个「中心主题」节点。
- **路径：**
  1. 双击中心主题，改成会议标题；
  2. 多次按 Tab / 点「子主题」，在左右两侧长出一级分支；
  3. 选中某分支按 Enter 加同级，或继续 Tab 加深层级；
  4. 拖动画布空白处平移，滚轮缩放，必要时点「适应」看全图；
  5. 对暂不关心的枝折叠，徽章显示隐藏子节点数。
- **高潮：** 整场讨论以中心辐射形态完整可见，结构清晰。
- **收尾：** 关闭窗口前可继续编辑；  
  `[ASSUMPTION: v1 至少支持会话内完整编辑；持久化（存盘 / 自动保存）在 MVP 内以实现「下次打开还能看到」为底线，格式可为自有 JSON。]`
- **边缘：** 误删非根节点后希望能撤销 —— 见 FR-撤销；根节点不可删除。

**UJ-2. 阿哲回顾一张已展开的大图，定位并修改某一枝。**

- **人物与情境：** 几天后回看技术方案枝。
- **进入状态：** 打开已有导图（或同一会话中的大图）。
- **路径：** 缩放 / 平移找到目标 → 单击选中 → 双击改文案 → 必要时增删子节点。
- **高潮：** 改动能立刻反映在布局与连线上，无需手工摆放。
- **收尾：** 选中态与工具条按钮状态一致（无选中时部分操作禁用）。

## 3. 术语表

下游实现与文档须沿用下列术语，避免同义替换。

| 术语 | 定义 |
|------|------|
| **导图（Mind Map）** | 以单个**中心主题**为根的一棵主题树，及在画布上的可视化呈现。 |
| **节点（Node）** | 树上的一个主题单元，含文案、子节点列表、折叠状态等。 |
| **中心主题（Root）** | 导图唯一的根节点；不可删除；布局上居中。 |
| **子主题** | 相对当前选中节点新增的子节点。 |
| **同级主题** | 与当前选中节点同一父节点、紧邻插入的兄弟节点；中心主题无同级。 |
| **侧（Side）** | 仅中心主题的直接子节点具备：`left` 或 `right`，决定向左或向右辐射；更深层级继承所在侧。 |
| **折叠** | 隐藏某节点的全部后代；布局不再为其分配空间。v1 原型曾用角标显示数量；**整理效率增量**改为分叉控件上的 **−N**（见后续 PRD）。 |
| **画布（Canvas）** | 承载节点与连线的无限平面；支持平移与缩放（相机）。 |
| **相机（Camera）** | 画布的平移与缩放变换；不改变节点世界坐标。 |
| **布局（Layout）** | 根据树结构与测量尺寸，计算每个节点的位置与连线几何（中心辐射）。 |
| **选中** | v1：操作焦点落在的**单个**节点。整理效率增量起升级为选中集，见 [整理效率 PRD](../prd-linva-organize-2026-09-25/prd.md)。 |
| **适应画布** | 调整相机，使当前可见内容大致落入视口。 |

## 4. 功能

### 4.1 单窗口工作台

**描述：** 应用以单个主窗口呈现：顶部工具条（品牌、节点操作、视图操作）+ 主画布。无多文档标签、无侧栏大纲（v1）。对应原型结构。实现 UJ-1、UJ-2。

**功能需求：**

#### FR-1：单窗口壳

用户打开 App 后进入唯一主窗口，包含工具条与画布区域。

**可验证结果：**
- 启动后可见品牌标识「Linva」与可用的节点 / 视图操作入口。
- 不存在第二文档窗口或标签切换（v1）。

#### FR-2：工具条状态

工具条根据是否选中节点、是否为中心主题，启用或禁用「子主题 / 同级 / 删除」。

**可验证结果：**
- 无选中时：上述节点操作均不可用（或等价于无效果且明确禁用）。
- 选中中心主题时：「同级」「删除」不可用；「子主题」可用。
- **折叠 / 展开不在工具条**（整理效率增量起改由画布分叉控件承担，见后续 PRD FR-O9）。v1 原生若仍保留工具条折叠，视为过渡，应对齐后续 PRD 后移除。

#### FR-2 历史说明

v1 初稿曾要求工具条承载折叠；2026-09-25 起以原型拍板为准，折叠迁出工具条。
---

### 4.2 主题树与编辑

**描述：** 用户通过工具条与键盘维护主题树：增子、增同级、改文案、删除、折叠。新建挂到中心主题下的一级节点时，系统在左右侧之间分配 **侧**。实现 UJ-1、UJ-2。

**功能需求：**

#### FR-3：默认导图

新会话（或新文件）包含唯一中心主题，初始文案可编辑（原型默认「中心主题」）。

**可验证结果：**
- 启动后至少存在一个中心主题节点并可被选中、编辑。

#### FR-4：添加子主题

在已选中节点上，用户可通过工具条「子主题」或快捷键 **Tab** 添加子主题；父节点若处于折叠则自动展开。挂到中心主题下时分配 `left` / `right`（策略：两侧数量大体均衡）。实现 UJ-1。

**可验证结果：**
- 新节点成为选中节点的子节点，并进入可编辑或已选中状态。
- 中心主题下新增一级节点具备明确的侧，并出现在对应一侧。

#### FR-5：添加同级主题

在已选中**非中心**节点上，可通过「同级」或 **Enter** 在同父下、当前节点之后插入同级；若父为中心主题，新节点继承（或按规则获得）侧。实现 UJ-1。

**可验证结果：**
- 中心主题上触发同级：无节点新增。
- 非根上触发：新兄弟插入在正确顺序位置。

#### FR-6：编辑文案

双击节点进入编辑；确认（如 Enter，不含 Shift+Enter 换行策略见假设）或失焦后写回；空文案回退为占位名（如「未命名」）。实现 UJ-1、UJ-2。

**可验证结果：**
- 编辑结束后画布上显示新文案，布局按新尺寸更新。
- `[ASSUMPTION: v1 支持单行或简单多行纯文本；富文本、Markdown 渲染不做。]`

#### FR-7：删除节点

可删除非中心主题节点（工具条或 ⌫ / Delete）；删除后选中其父节点。中心主题不可删。

**可验证结果：**
- 删除后该子树从导图中消失，布局收缩。
- 对中心主题执行删除：无效果。

#### FR-8：折叠与展开

对有子节点的节点可折叠 / 展开；折叠后后代不可见且不占布局空间。

**可验证结果：**
- 折叠后后代不可见且不占布局空间；展开后恢复。
- 无子节点时折叠操作不可用。

**交互入口（2026-09-25 修订）：** 主入口为画布**分叉控件**（＋折叠 / −N 展开），详见 [整理效率 PRD](../prd-linva-organize-2026-09-25/prd.md) FR-O9～O11。不再以工具条按钮为主入口。

#### FR-9：选中

单击节点选中；单击画布空白取消选中（或等价清晰行为）。选中有明显视觉反馈。

**可验证结果（v1 里程碑）：**
- 任意时刻至多一个选中节点。

**后续：** 多选、框选、Shift 连选见 [整理效率 PRD](../prd-linva-organize-2026-09-25/prd.md)。实现整理效率后，本条「至多一个」废止，以该 PRD 为准。
---

### 4.3 中心辐射布局

**描述：** 系统根据主题树自动计算节点位置与连线，中心主题居中，一级主题分左右向外延伸，更深层级沿所在侧继续延伸。用户无需手工摆坐标。实现 UJ-1、UJ-2。

**功能需求：**

#### FR-10：自动布局

任意改树操作（增删改文案、折叠）后，布局更新，节点大致不重叠，连线连接父子。

**可验证结果：**
- 与原型一致：左右分侧、垂直按子树高度堆叠、水平按间距外推。
- 中心主题视觉权重高于普通节点（尺寸 / 样式区分）。

#### FR-11：连线

父子之间绘制曲线（或等价清晰连线），位于节点之下、不阻挡点选。

**可验证结果：**
- 每个可见的父子关系有且仅有一条连线（折叠隐藏的除外）。

---

### 4.4 画布导航

**描述：** 用户通过拖拽空白平移、滚轮（或等价手势）缩放、工具条缩放与「适应」浏览大图。实现 UJ-1、UJ-2。

**功能需求：**

#### FR-12：平移与缩放

拖拽画布空白平移；滚轮以指针为锚点缩放；工具条提供放大 / 缩小与缩放比例展示。

**可验证结果：**
- 缩放范围有合理上下限（原型约 25%–250% 量级即可）。
- 缩放时世界内容相对指针位置稳定（锚点缩放）。

#### FR-13：适应画布

「适应」将当前可见内容纳入视口（可带动画）。

**可验证结果：**
- 点击后整图（或当前展开内容）大致居中可见。

---

### 4.5 快捷键

**描述：** 键盘加速与原型对齐，降低工具条依赖。实现 UJ-1。

**功能需求：**

#### FR-14：核心快捷键

在非编辑态：`Tab` 子主题、`Enter` 同级、`⌫`/`Delete` 删除（非根）、可选 `/` 或约定键折叠。编辑态：`Enter` 提交、`Esc` 取消或提交（与原型一致并在实现中固定一种）。

**可验证结果：**
- 与工具条同一套命令，行为一致。
- 编辑态不误触发全局快捷键。

---

### 4.6 持久化与撤销（MVP 底线）

**描述：** 保证工作不白费，并允许纠正误操作。  
`[ASSUMPTION: 持久化与撤销列入 MVP；若排期紧张，可先交付「导出会话 JSON + 导入」作为持久化最小形态，再补原生文件关联。]`

**功能需求：**

#### FR-15：保存与打开

用户可将当前导图保存到本地并再次打开。  
`[ASSUMPTION: v1 使用自有文件格式（如 `.linva` / JSON），不兼容 XMind 专有格式。]`

**可验证结果：**
- 保存 → 退出 → 打开后，树结构与文案一致（折叠状态是否持久化需在实现时固定并测试）。

#### FR-16：撤销 / 重做

对改树类操作支持撤销与重做（至少覆盖增删、改文案、折叠）。

**可验证结果：**
- 连续撤销可回到先前状态；重做可前进。
- `[ASSUMPTION: 快捷键为 ⌘Z / ⇧⌘Z（macOS 惯例）。]`

## 5. 非目标（明确不做）

v1 **不是** 也 **不会做成**：

- 多文档 / 文档浏览器 / iCloud 同步
- 云端协作、评论、权限
- 大纲视图、演示模式、多种版式模板（组织图、鱼骨等）切换
- 跨枝「关联线」、自由拖拽脱离树的坐标布局
- 主题商店、复杂样式系统、附件 / 图片节点
- 导入导出 XMind / OPML / Markdown（可列入后续）
- iOS / iPadOS 客户端
- 账号体系与付费订阅

技术实现细节（Metal 管线、文字纹理策略等）不属于本 PRD 能力描述，见 `addendum.md`。

## 6. MVP 范围

### 6.1 范围内

- 单窗口工作台（FR-1、FR-2）
- 主题树 CRUD + 折叠 + 选中（FR-3–FR-9）
- 中心辐射自动布局与连线（FR-10、FR-11）
- 画布平移 / 缩放 / 适应（FR-12、FR-13）
- 核心快捷键（FR-14）
- 本地保存打开 + 撤销重做（FR-15、FR-16）
- 交互与信息架构对齐已认可的 HTML 原型

### 6.2 MVP 范围外（可排期到后续）

| 项 | 原因 / 状态 |
|----|------|
| 多选、框选、分叉折叠交互升级 | **已开增量 PRD：** [整理效率](../prd-linva-organize-2026-09-25/prd.md) |
| 拖拽改层级 | 依赖多选与落点；整理效率之后 |
| 多文档 / DocumentGroup | 先证伪单图核心体验 |
| 富文本 / Markdown 节点 | 先保证纯文本编辑闭环 |
| 导出 PNG/MD | **PNG + MD 已开增量 PRD：** [导出](../prd-linva-export-2026-09-25/prd.md)；PDF 已移除（不再做） |
| 多种布局模式 | v1 只做中心辐射 |
| 深色模式 / 完整主题系统 | 视觉可后置 |

## 7. 成功指标

**主指标**

- **SM-1：核心闭环可完成** — 在原生 App 中独立完成 UJ-1（建树、编辑、折叠、导航），无需依赖 HTML 原型。验证 FR-3–FR-14。
- **SM-2：方向可证伪** — 在约 100 量级节点下，平移缩放仍可交互（主观流畅即可）。验证 FR-10、FR-12。  
  `[ASSUMPTION: 具体帧率指标待性能基线后再量化。]`

**次指标**

- **SM-3：可回访** — 保存后再次打开内容不丢（FR-15）。
- **SM-4：误操作可恢复** — 误删后可通过撤销找回（FR-16）。

**反向指标（不要优化成）**

- **SM-C1：功能堆砌** — 不以「功能数量接近 XMind」为成功；避免为对标而膨胀范围。
- **SM-C2：过早打磨视觉** — 不以像素级视觉完美阻塞主链路可用。
