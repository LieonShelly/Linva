# PRD：YMind — 节点内嵌图片（图 + 文共存）

## 0. 文档目的

本文描述节点内嵌图片增量：**粘贴 / 拖入图片进节点，节点同时显示图片与文字，随文档持久化，随导出交付**。图片功能是思维导图类 App 的成熟度基线（XMind / MindNode 官方核心能力），决策为「做」（ICE 11.6），排期 **A：进 1.0，与迁移闭环并行开发**。

- **上游：** [v1 PRD](../prd-ymind-2026-09-24/prd.md)；[迁移闭环 PRD](../prd-ymind-import-export-2026-09-30/prd.md)（并行开发，见 §4.5 接缝）
- **需求真源：** [机会卡片](../../pm/opportunities/2026-09-30-节点图片功能.md)（FR 编号 G1…G6 与卡片一致）
- **体验真源：** `prototype/image-node.html`（粘贴插图 / 图文同框 / 导出含图）
- **明确不在本增量：** 图片 URL / 网络图、多图节点、图片标注编辑、附件文件（v1.1+）；Markdown 图片导入。

文档语言：中文优先。

---

## 1. 愿景与要完成的工作

YMind 节点目前只有文字（`Node.text` + 填色）。用户在读书笔记、方案拆解、设计整理时想把**截图 / 参考图 / 素材**直接贴进节点，和文字一起表达——「图能说清的事不用打字」，且导图交付时图片跟着走。

三条主链路：
- **进得来：** 选中节点 → ⌘V 粘贴剪贴板图片，或拖入图片文件；再次粘贴替换，⌫ 清除。
- **同框显示：** 节点 = 图片 + 文字同框；布局尺寸合成（宽取 max、高叠加），显示宽度有上限不撑爆导图。
- **出得去：** PNG / PDF 导出含图；Markdown 降级（文字结构 + 图片忽略或引用）。

成功标准（SM 见 §6 语境）：阿哲能把截图贴进节点并随图导出交付，图文共存不影响布局稳定性。

## 2. 关键用户旅程

**UJ-G1. 阿哲把一张设计参考图贴进方案节点。**

1. 选中节点「视觉稿参考」，⌘V 粘贴剪贴板截图；2. 节点立即显示图 + 原文字同框，布局自动重排；3. 不想要时 ⌫ 清除或再粘一张替换；4. ⌘Z 可撤销整步。

**UJ-G2. 阿哲导出含图导图交给同事。**

1. 文件 → 导出 → PDF…（迁移闭环）；2. 图中节点带图，直接可打印/预览；PNG 同理；3. Markdown 导出仍为纯文字结构（图不丢导图，仅不进入 MD）。

## 3. 术语表（增量）

| 术语 | 定义 |
|------|------|
| **节点图片** | `Node` 上的 `image` 数据（内嵌，base64 于 `.ymind`）；节点可同时有 `text` 与 `image`。 |
| **图文同框** | 节点的布局与显示把图片和文字放在同一节点框内：宽取 max、高叠加。 |
| **显示宽度上限** | 图片在画布上的最大显示宽度（默认 ≤300pt），超出等比缩放、不裁切；参照 MindNode clamp 行为。 |
| **图片替换 / 清除** | 再次粘贴/拖入 = 替换；⌫ 或菜单 = 清除（两者都是命令栈一步，可撤销）。 |

## 4. 功能需求

### 4.1 图片存储与编解码

**描述：** 图片以**内嵌数据**持久化在 `.ymind`（文件自包含，复制/移动不丢链）；Codec 升 v3 并迁移。实现 UJ-G1。

**功能需求：**

#### FR-G1：Node.image 字段与 Codec v3

用户粘贴/拖入的图片作为 `Node.image`（`Data?`，内嵌 base64）持久化；旧版本文件（v2 无 `image`）正常打开。

**Consequences（可测）：**
- `Node` 增 `image: Data?`（Codable，缺省 nil）；`NodeFrame` 携带图片尺寸/纹理引用信息。
- `MindMapDocument.currentVersion` 升 **3**；`YMindCodec` 内置 v2→v3 迁移：缺失 `image` 视为无图，旧文件零拒绝。
- `sanitize` 规则不变（`side` 消毒、根约束等）；`encode` 前对图片做尺寸/体积上限处理（见 §8 addendum）。
- 空/损坏图片数据在 decode 时容错（视为无图，不崩溃）。

**Out of Scope：** 外链文件引用（断链风险）；图片 URL。

#### FR-G2：粘贴 / 拖入 / 替换 / 清除

选中节点后，用户可通过 ⌘V 粘贴剪贴板图片、拖入图片文件、再次粘贴替换、⌫ 或菜单清除图片。

**Consequences（可测）：**
- ⌘V：读剪贴板图片类型（`NSPasteboard.PasteboardType`，png/tiff 等）→ 归一为 PNG → 入命令栈 `setImage`；无可粘贴图片时无操作且给状态提示。
- 拖入：图片文件（png / jpeg / gif / tiff / heic）拖到节点 → heic 转 PNG、其余归一 PNG；非图片文件忽略。
- 替换：已有图时再次粘贴/拖入 = 一步 `setImage` 覆盖（撤销回上一张）。
- 清除：⌫ / 菜单「清除图片」= 一步 `clearImage`。
- 无选中节点时粘贴/拖入图片：无效果（或提示先选节点）。

**Out of Scope：** 拖拽图片新建节点（与 XMind 8 行为差异，v1.1 评估）；粘贴进 note/备注。

### 4.2 图文同框布局

**描述：** 节点尺寸 = 文字与图片合成；图片显示宽度有上限。实现 UJ-G1。

**功能需求：**

#### FR-G3：布局尺寸合成

有图节点的 `NodeSize` 由文字与图片共同决定：宽 = max(文字宽, 图片显示宽 + 边距)，高 = 文字高 + 图片高 + 边距。

**Consequences（可测）：**
- 有图节点布局后框内同时容纳图片与文字，且与无图节点/连线不重叠。
- 显示宽度上限可配置（默认 300pt；见 §4.3 原型切换验证），超出等比缩放、不裁切。
- 折叠 / 命中 / 选中 / 搜索行为与无图节点一致（图片不改变节点语义）。

**Out of Scope：** 图片自由缩放/拖拽定位（固定上限，点击看原图 v1.1+）。

### 4.3 图片渲染

**描述：** 复用既有文字纹理管线（CGImage → MTLTexture → quad 采样）；Retina 对齐；脏键缓存。实现 UJ-G1。

**功能需求：**

#### FR-G4：图片纹理渲染

有图节点在画布上绘制图片纹理（+ 文字），缩放平移正确、Retina 清晰、图变才重建纹理。

**Consequences（可测）：**
- 图片以纹理形式与文字同框绘制；`displayScale` 对齐 Retina（复用文字纹理的 scale 路径）。
- 纹理缓存按脏键（图片数据/尺寸变化）失效重建，不随相机平移缩放重传。
- 图片绘制不新增层间依赖（沿用 Render 白名单：AppKit/CoreGraphics/Metal/MetalKit）。

**Out of Scope：** 图片滤镜 / 形状遮罩 / 动图（gif 取首帧静态）。

### 4.4 导出含图

**描述：** 图片随导出走：PNG / PDF 含图，Markdown 降级。实现 UJ-G2。

**功能需求：**

#### FR-G5：PNG / PDF 含图，Markdown 降级

导出的 PNG / PDF 包含节点图片；Markdown 导出保持纯文字结构。

**Consequences（可测）：**
- **PNG**（既有 FR-E3 全展开导出）：Metal 离屏渲染含图片纹理，导出图节点带图。
- **PDF**（迁移闭环 FR-E1 管线）：PDF 页面含节点图片。
- **Markdown**：默认忽略图片只出文字结构（可选：输出 `![图片](…文件名…)` 引用——实现时定，默认忽略）。
- 图片上限（≤1024px 压缩）保证导出体积合理。

### 4.5 与迁移闭环的并行接缝

**描述：** 图片功能与迁移闭环（另一开发终端）同动 Layout / Render / 导出；本 PRD 定义接缝避免合并冲突。

**功能需求：**

#### FR-G6：接缝契约

图片功能与迁移闭环在共享模块上以 `LayoutSnapshot` 契约为界，互不破坏。

**Consequences（可测）：**
- **Codec**：迁移闭环明确「`currentVersion` 保持 2、不加字段」；图片功能将其升 **3**——两者不相交（迁移闭环不动版本号），图片以迁移闭环合并后的 main 为基线或独立分支，**以版本号独占方式升 v3**。
- **Layout**：图片功能扩展 `NodeSize`/`NodeFrame` 的尺寸合成；迁移闭环的 PDF 复用同一 `LayoutSnapshot`——图片尺寸进 `NodeFrame` 后 PDF 导出自动继承，无二次改动。
- **Render**：图片纹理作为新增 quad 采样，与文字纹理管线并存；迁移闭环的 `renderImage`（PDF/PNG 共用 `encodeContent`）天然携带图片。
- **命令**：新增 `setImage` / `clearImage` 两命令（仿 `setFill` 先例），与迁移闭环命令互不依赖。
- `scripts/check-boundaries.sh` 白名单**不新增 import**；合并后构建期校验全绿。

## 5. 非目标（明确不做）

- 图片 URL / 网络图；多图节点 / 相册管理；图片标注、裁剪、滤镜编辑（压缩上限除外）。
- 视频 / 音频 / 附件文件节点（附件功能另行评估）。
- Markdown 图片导入（与迁移闭环 FR-I1 边界）；拖拽图片新建节点（v1.1）。
- 图片自由缩放拖拽、动图播放（gif 取首帧）。

## 9. 开放问题

1. **图片体积上限**：`[ASSUMPTION: 压缩到 ≤1024px + 体积上限（如 ≤5MB）]`——具体值实现时定（防 `.ymind` 文件膨胀与显存膨胀）。
2. **Markdown 导出降级**：忽略 vs 输出 `![图片]` 引用——默认忽略，实现时可顺手输出引用。
3. **拖拽图片到空白画布**：是忽略还是新建图片节点（XMind 8 曾如此）——默认忽略，v1.1 评估。
4. **gif 动图**：默认取首帧静态（不做动画），确认接受。
5. **粘贴图片在「编辑文案中」时**：先提交文字再贴图（避免与 IME 冲突）——实现时定，默认先提交。
