# YMind 当前工程架构说明

**状态：** 基于 `main` 已实现代码的实况梳理（非仅设计稿），随增量持续更新  
**日期：** 2026-10-01  
**范围：** `YMindApp/` 原生 App（MVP 已跑通：建树、中心辐射布局、Metal 文字、编辑、存盘 Undo；增量：搬枝 / 多选 / 剪贴板、排序 / 搜索 / 改侧、填色、框选与工具模式、Markdown/PNG 导出、导入 Markdown/OPML/FreeMind、自动保存 / 崩溃恢复、窗口态桥接）  
**对照：** `docs/superpowers/specs/2026-09-24-ymind-v1-architecture-design.md`、`docs/prds/prd-ymind-2026-09-24/prd.md`

**绘图约定：** 使用 Mermaid。

---

## 1. 一句话结论

当前是 **「分层内核 + DocumentSession 门面 + SwiftUI/Metal 薄壳」**：改树走命令、几何走 LayoutSnapshot、像素走 Metal，**主干扩展性够用**；多选/框选、搬枝、样式、导出、导入（注册表）、自动保存/崩溃恢复已按这套接口长出；若要上多布局、跨枝关联线、多文档，还需要在 Session / Layout / Model 三处做**有计划的接口化**，而不是推倒重来。

## 4. 运行时数据流

### 4.1 改树（增删改折叠）

```mermaid
sequenceDiagram
  participant UI as ContentView / 菜单 / 快捷键
  participant DS as DocumentSession
  participant Bus as CommandBus
  participant Model as MindMapModel
  participant Lay as RadialLayout
  participant Metal as MetalRenderer

  UI->>DS: commandBus.execute(...)
  DS->>Bus: execute
  Bus->>Model: 变更树 + 记录可逆快照
  Bus-->>DS: onChange
  DS->>DS: selectedId / undoRevision / isDirty
  DS->>Lay: layout(document, measure)
  Lay-->>DS: snapshot
  DS-->>UI: @Published 刷新
  UI->>Metal: draw(snapshot, camera, selectedIds, intent, searchHit, marquee)
```

### 4.2 相机（不入命令栈）

平移 / 滚轮缩放 / 适应画布只改 `DocumentSession.camera`，**不**触发 `CommandBus`，也**不**写入 `.ymind`。

### 4.3 编辑文案

双击 → `startEditing` → 浮层改 `draftText` → 提交时 `SetText` 入命令栈 → 重布局 → 纹理缓存按脏键重建。

## 5. 依赖规则（实况）

> **强制机制（2026-09-27）：** 本表已由 `scripts/check-boundaries.sh` 在构建时强制（build phase「依赖边界校验」，违规即红）。白名单与下表一致。新增依赖必须同步更新脚本白名单与本表。

| 层 | 允许 import（白名单，与脚本逐字一致） | 禁止 / 说明 |
|----|-----------------------------------------|-------------|
| Model / Commands | `Foundation` | 严禁 SwiftUI / Metal / AppKit；`XMLParser` 属 Foundation，导入器可用 |
| Layout | `Foundation` `AppKit` `CoreGraphics` `CoreText` | 量字需要字体；不碰 Metal |
| Session | `Foundation` `Combine` `CoreGraphics` | 门面编排，无 UI |
| Render | `Foundation` `AppKit` `CoreGraphics` `ImageIO` `Metal` `MetalKit` `SwiftUI` `simd` | 只吃 `LayoutSnapshot`，不懂树；ImageIO：ImageTextureCache 降采样解码（2026-10-01 图片节点） |
| App / Shell | `Foundation` `AppKit` `SwiftUI` `ImageIO` | 尽量不直接深改 Model（多数经 Session / Bus）；ImageIO：图片归一器 CGImageSource 解码（2026-10-01 图片节点） |

**根目录两个文件**（`ContentView.swift` / `YMindAppApp.swift`，属 App 层）：实际 import 还含 `UniformTypeIdentifiers`（`DocumentWorkflow` 的 NSOpenPanel/NSSavePanel 内容类型声明）。此模块为 SwiftUI/AppKit 伴生框架、纯 UTI 声明，无分层风险；`check-boundaries.sh` 只扫 6 个分层目录，不覆盖根目录文件，现状放行。

**边界亮点：** `MetalRenderer.draw(..., snapshot:camera:selectedIds:)` 不理解父子关系——换布局算法或换渲染后端时，Snapshot 契约是稳定接缝。`PNGExporter` 也走同一 `LayoutSnapshot` + `MetalRenderer.renderImage`，导出不碰 Model 的会话态。导入侧 `DocumentImporterRegistry`（Model，纯函数 `parse(Data)`）按扩展名路由，新增格式（XMind v1.1）注册即插，不碰 Session/Shell。

## 6. 关键类型契约（扩展时优先保住）

```mermaid
classDiagram
  class MindMapDocument {
    +Int version
    +Node root
  }
  class Node {
    +UUID id
    +String text
    +Bool collapsed
    +Side? side
    +NodeFill? fill
    +Data? image
    +ImagePixelSize? imagePixelSize
    +Node[] children
  }
  class LayoutSnapshot {
    +frames: UUID to NodeFrame
    +edges: EdgeGeometry[]
    +imagePayloads: UUID to ImagePayload
  }
  class NodeFrame {
    +id text center size
    +isRoot side collapsed hiddenCount
    +fill: NodeFill?
    +imageRect: CGRect?
  }
  class DocumentSession {
    +model commandBus
    +snapshot camera
    +fileURL isDirty
    +selectedIds: Set~UUID~
    +canvasTool search
    +editingId draftText
    +documentID: UUID
    +importPreview: ImportPreviewState?
    +recovery: RecoveryOffer?
  }
  MindMapDocument --> Node
  DocumentSession --> MindMapDocument : via model
  DocumentSession --> LayoutSnapshot
  RadialLayout ..> LayoutSnapshot : 产出
  MetalRenderer ..> LayoutSnapshot : 消费
```

文件格式：`.ymind` = versioned JSON（`MindMapDocument.currentVersion == 3`）；`YMindCodec` 负责版本校验、v1→v2→v3 迁移与深层 `side` 消毒。v2 新增 `Node.fill`（节点填色）；v3 新增 `Node.image` / `imagePixelSize`（节点内嵌图片，见 §17）。导入产出的也是 v3 文档（`MarkdownImporter` / `XMLImporters` 显式带 `currentVersion`）。

**命令清单（13 个，全部经 `CommandBus` 可逆）：** `addChild` / `addSibling` / `delete` / `setText` / `toggleCollapse` / `setCollapsed` / `moveToParent` / `insertSiblings` / `setSide` / `applyRootSide` / `pasteAsChild` / `setFill` / `setImage`。

## 7. 扩展性评估

### 7.1 总评

| 维度 | 评分 | 说明 |
|------|------|------|
| 分层清晰度 | 高 | Model / Command / Layout / Render 边界与设计一致 |
| 可测性 | 高 | 内核单测扎实（16 文件 2418 行，含导入器/自动保存/会话）；Metal/菜单/SavePanel 入口偏手测 |
| 加同类命令（如改色） | 高 | 新 `MindMapCommand` + Bus 分支即可 |
| 加第二种布局 | 中 | 需抽出 `LayoutEngine` 协议；Snapshot 可复用 |
| 多选 / 框选 | ✅ 已实现 | `selectedIds: Set<UUID>` + 锚点 + 框选命中（§13） |
| 手动改侧 / 搬枝 | ✅ 已实现 | `setSide` / `applyRootSide` / `insertSiblings`（§11） |
| 跨枝关联线 / 自由图 | 低～中 | 现模型是**树**；需边表或图模型，布局与命中都要扩 |
| 多文档 / DocumentGroup | 中 | Session 已封装单文档；上多文档要多 Session 实例 + 窗口策略 |
| 主题 / 样式系统 | 中 | 样式字段可进 Node；Render 已按 frame 绘制，要扩 `NodeFrame` |
| 导出 Markdown / PNG | ✅ 已实现 | `MarkdownExporter` / `PNGExporter`，纯函数 + 离屏渲染（§14） |
| 导入 MD/OPML/FreeMind | ✅ 已实现 | `DocumentImporterRegistry` 注册表 + 预览确认（§16）；XMind 注册即插 |

### 7.2 容易加上的功能（架构友好）

- 新可逆操作：重命名风格、批量设折叠、节点备注（纯文本字段）
- 布局常量 / 间距主题微调
- 只读演示模式（禁用 CommandBus）
- 更丰富的快捷键（仍走同一 `execute`）
- Codec `version` 升迁（加字段 + 迁移）

### 7.3 需要先「开刀接口」再加的功能

| 目标 | 建议改造 |
|------|----------|
| 多种布局（逻辑图、组织图） | `protocol LayoutEngine { func layout(document:measure:) -> LayoutSnapshot }`；Session 持有当前 engine |
| 手动改侧 / 拖拽改层级 | ✅ 已实现（§11）：`setSide` / `applyRootSide` / `insertSiblings` + `DropIntent` 命中分区 |
| 多选 | ✅ 已实现（§11/§13）：`selectedIds: Set<UUID>`、命令多目标、框选加选 |
| 节点样式（颜色、图标） | ✅ 填色已实现（§12）：`Node.fill` / `NodeFrame.fill`、Metal 画填充色、Codec v2；图标仍未做 |
| 富文本 | 编辑浮层换 `NSTextView` 属性串；量字与纹理策略变复杂——建议独立里程碑 |
| 关联线（非树边） | 新增 `links: [(from,to)]`；Layout 输出额外边；命中区分 |

### 7.4 当前结构上的薄弱点（强壮度风险）

```mermaid
flowchart LR
  subgraph Risk["需留意的耦合"]
    DS2["DocumentSession 职责偏多"]
    CV2["ContentView 含业务编排"]
    Sel["多选语义分散（模型/Session/视图各持一份）"]
    Lay2["RadialLayout 写死算法"]
  end
```

1. **`DocumentSession` 门面过重**  
   文件 I/O、脏标记、选中、编辑草稿、布局、相机、错误文案、导入预览、自动保存防抖、恢复态集于一类（548 行，仍在长）。后续功能继续堆会导致难测、难拆。  
   **建议：** 保持对外 API，内部拆 `EditingController` / `Persistence`（含 Autosave）/ `LayoutPipeline`（仍由 Session 组合）。

2. **`ContentView` 直接 `commandBus.execute` 并夹带「加完就编辑」**  
   业务散落在 View。  
   **建议：** 收敛为 `session.addChildAndEdit()` 等用例方法，View 只绑事件。

3. **布局与渲染的 Snapshot 字段偏「辐射布局专用」**  
   `side`、`hiddenCount` 仍可用，但若组织图要不同边几何，需扩展 `EdgeGeometry` 而非改 Metal 懂业务。

4. **工程仍是单 target**  
   分层靠目录约定，编译器不强制。模块化（SPM）可后置，但目录纪律要守。

5. **渲染文字路径已踩过坐标系坑**  
   纹理栅格化 + UV 已用「AppKit 绘制 + 行翻转」稳住；后续改 TextAtlas 时保持回归截图/手测。

## 10. 小结（给产品 / 自己看的判断）

- **现在这套架构足以支撑「在树上继续加能力」**，MVP 验证目标已达成。  
- **够不够强壮，取决于扩展类型：**  
  - 命令、样式、导出、第二种布局（接口化后）→ 强壮、可加。  
  - 多选、自由图、协同 → 要演进模型，但**不必推翻 Metal / Session 主链路**。  
- **最大技术债**不是 Metal，而是 **Session / View 用例边界** 与 **Layout 单实现**；优先还这两笔，扩展成本最低。

## 11. 增量：同级排序 + 搜索定位 + 手动改侧（2026-09-26）

在既有搬枝 / 多选 / 剪贴板之上，一次落地三份 PRD（`docs/prds/prd-ymind-reorder|search|side-2026-09-25`），共用**同一个节点操作底座**：

- **`DropIntent`**（`Session/DropIntent.swift`）：统一「成子 / 插前 / 插后 / 改侧」四类放置意图，替换原 `dropTarget: UUID?`。纯函数 `resolveDropIntent` 按节点分区（非中心上/下 28% → before/after，中部 → child；中心左/右 1/3 → 改侧带，中部成子），空白过中线仅当被搬顶层全为一级枝才产生改侧意图。
- **Model**：`insertSiblings`（跨父连续块、中心下继承锚点 side）、`setSide`（仅一级枝）、`applyRootSide`（提升或改侧）、`searchMatches`（DFS 先序、大小写不敏感、含折叠子树）。
- **Command**：`insertSiblings` / `setSide` / `applyRootSide` 各为命令栈一步 Undo。
- **Session**：`SearchState`（open/query/matches/index）与 `revealSearchMatch`（展开祖先 → 选中 → 居中）；`Camera.center(on:viewport:)` 保持缩放居中。
- **Render**：放置反馈按意图（插入线 / 根镶边 / 中线引导）、搜索命中琥珀色高亮，全部走既有 `drawSolid` 管线，无新 shader。
- **Shell**：搜索浮层（`App/SearchBar.swift`）、工具条改侧按钮、⌘F/⌘G/⇧⌘G/⌘←/⌘→ 菜单快捷键。

分层纪律保持不变：Model/Command 仅 Foundation；Metal 只消费 Snapshot + 会话态；搜索与放置意图为会话态不入 `.ymind`。

## 17. 增量：节点内嵌图片（2026-10-01）

落地 `docs/superpowers/specs/2026-10-01-ymind-image-node-design.md`（FR-G1~G5）：图片可粘贴/拖入为节点内嵌属性，随 `.ymind` 持久化、随布局/渲染/导出贯通。

- **Codec v3**：`MindMapDocument.currentVersion` 升到 3；`YMindCodec` 内置 v1→v2→v3 迁移（v3 仅版本号升迁，`image`/`imagePixelSize` 缺省 nil，Node 解码器天然容错）。`Node.image: Data?`（归一后 PNG bytes）+ `Node.imagePixelSize: ImagePixelSize?`。`ImagePixelSize` 为自有类型（failable init：宽高 >0 且有限；解码时非法尺寸 → nil 视为无图，不拒文件；CGSize 在 `import Foundation` 下不可 Codable，Model 白名单禁 CoreGraphics）。
- **图片归一器**（`App/ImageNormalizer.swift`，FR-G1 入口）：`CGImageSource` 解码（gif 取首帧）→ 最长边 >1024 等比降采样 → PNG 编码 → 仍 >5MB 再降 512 → 仍超限返回 nil（调用方提示，不入栈）。Session 持 `imageNormalizer` 注入点（App 组合根注入、测试 stub；Session 白名单无 ImageIO）。
- **Session 图片入口**（FR-G2 修订）：`setPastedImage(from:)`（粘贴/拖入：归一 + 入栈，需有选中节点）、`setImage(_:pixelSize:)`（写/清图片；清除时若处于图片级选中，目标为被选图片所在节点，⌫ 分派）；图片级选中 `selectedImageId: UUID?`（节点内子元素、不入命令栈、同时最多一个；清图/换选/点空白/Esc 后回落选中回节点）。
- **Command**：`setImage(ids:image:pixelSize:)` 一步 Undo、无变化 no-op 不入栈；**§6 命令清单 12 → 13**。
- **图文同框布局**（FR-G3）：`NodeFrame.imageRect: CGRect?`（节点局部坐标，top-left 原点：图在上、文字在下，水平居中）；显示宽 = `min(像素宽, 300pt)`（`LayoutConstants.imageMaxDisplayWidth`），高按宽高比，图文间距 `imageTextGap = 6`；`LayoutSnapshot.imagePayloads: [UUID: ImagePayload]`（Layout 从 Model 拷出像素数据 + 尺寸，Render 只消费 Snapshot，仍不懂树）。
- **纹理三纪律**（`Render/ImageTextureCache.swift`，FR-G4）：① **视口剔除** —— `evictUnused(known:)` 释放不在可见帧集合内的条目，回屏按需重建；② **降采样解码** —— CGImageSource thumbnail 按显示尺寸 × scale 解码，不全尺寸加载；③ **LRU 128MB 字节预算**驱逐（`byteBudget` 默认 128MB）。脏键 = 节点 id + 显示像素尺寸 + scale 桶 + **内容身份**（命中 O(1) baseAddress/count 比对；条目持有 Data 值锁定缓冲区，杜绝地址复用误命中；miss 重建时才算 FNV-1a 全哈希并 memoize）。不用 `Data.hashValue`（实测 NSData.hash 只取前缀字节），也不再用「字节数 + 首尾 8 字节」——本应用图片全为 PNG，prefix/suffix 恒为文件签名/IEND 尾，等长替换会全碰撞显示旧图。数据非法/解码失败 → nil 按无图显示，降级不崩。
- **Render 消费**：`MetalRenderer` 画图片 quad（视口剔除 + 缓存），图片级选中画描边；命中走 `CanvasHitTesting.hitTestImageRect`（双击图片区 → `session.selectImage` 进图片级选中；选中图片时 ⌫ 只清图、Esc 先退图片选中）；PNG 导出自动含图。
- **Markdown 文件夹包导出**（FR-G5 修订：MD 含图）：`MarkdownOutput`（text + images: `[MarkdownImage]`）、`MarkdownImage`（nodeId + data，导出为 `assets/<id>.png`）；有图节点行内尾缀 `![图片](assets/<id>.png)`；**有图 → 文件夹包（`N/N.md` + `assets/`），无图 → 单文件不变**（`MarkdownExporter` 在 Model，仅 Foundation）。
- **测试**：新增 `ImageNormalizerTests`（106 行：降采样/HEIC 转 PNG/16-bit 二级降级/往返）、`ImageTextureCacheTests`（117 行：脏键/驱逐/降级/**等长 PNG 重建回归**）；Codec / Layout / Session / 命令栈 / Markdown 导出既有套件补图片用例。

分层纪律不变：Model 仅 Foundation（`ImagePixelSize` 自有类型替代 CGSize）；App 归一器用 ImageIO（已在白名单）；Render 纹理缓存用 ImageIO 降采样解码（已在白名单）；Render 只消费 `LayoutSnapshot.imagePayloads`，不碰 Model；图片级选中为会话态不入 `.ymind`、不入命令栈。
