## 2. 分层架构（核心）

思维导图类 App 的通用拆法，也是 Linva 的主链路：

```text
Interaction（手势、快捷键、选中、Undo）
        ↓
   Layout（CPU：树 → 各节点 frame / 连线路径）
        ↓
   Model（主题树 + 命令）
        ↓
   View（Metal 画像素；SwiftUI 管壳与编辑浮层）
```

**原则：**

- **几何与业务在 CPU，像素在 GPU。**
- Metal **不理解**父子关系，只消费「本帧要画的矩形、曲线、字形」。
- Model 变更 → 触发布局 → 再绘制；拖拽平移缩放优先改 **相机**，松手或改树后再写回 Model。

建议实现顺序：**Model + 布局（可单测）→ SwiftUI↔Metal 通路 → 命中与编辑 → Undo / 存盘**。

## 3. 数据模型

| 点 | 说明 |
|----|------|
| 结构 | **单根树**（不是自由图）；关联线等跨枝边 v1 不做 |
| 节点字段 | `id`、文案、`children` 有序数组、`collapsed`、样式（可后置） |
| **侧（side）** | 仅**中心主题的直接子节点**存 `left` / `right`；更深节点继承所在侧 |
| 顺序 | `children` 数组顺序 = 同侧从上到下的阅读顺序 |
| 新建一级侧 | 按左右数量大致均衡自动分配（原型已实现） |
| 序列化 | 导图本质是树的 JSON（或自有 `.linva`）；不是截图 |

伪结构（概念，非最终 API）：

```text
MindMapDocument
  └─ root: Node
       ├─ text, collapsed, children[]
       └─ children[].side?   // 仅根下第一层
```

## 4. 中心辐射布局（CPU）

| 点 | 说明 |
|----|------|
| 输入 | 主题树 + 节点测量宽高（由文案决定） |
| 输出 | `节点 id → AABB/中心点` + 父子连线控制点 |
| 算法骨架 | 自底向上算子树高度 → 一级拆 left/right → 两侧按子树高度垂直堆叠 → 水平按间距外推 → 根放世界原点附近 |
| 折叠 | 子树高度视为 0（或仅保留节点自身），布局自然收缩 |
| v1 不做 | 交叉边优化、复杂避让、布局补间动画（可后补） |

原型参考：`prototype/app.js` 中 `layoutTree` / `placeBranch` / `placeSide`。

## 5. 渲染与视图

| 点 | 说明 |
|----|------|
| 为何不用大量 SwiftUI View 当节点 | 节点一多会层爆炸；画布级内容适合 Canvas/Metal |
| Metal 画什么 | 清屏 → 连线 → 节点背景（可实例化四边形）→ 文字 |
| 文字策略（待定） | Core Text 量字 + 纹理缓存 / 离屏栅格化上传；**改字后脏节点更新** |
| Retina | `contentsScale` 与坐标、命中必须对齐 |
| 相机 | `translation` + `scale`；缩放以指针为锚点（原型已做） |
| 绘制顺序 | 线在节点下；选中态在最上 |

SwiftUI 与 Metal 的接法（概念）：

```text
ContentView（工具条）
  └─ NSViewRepresentable → MTKView（画布）
       └─ 编辑时叠 TextField / 其它 AppKit/SwiftUI 控件
```

## 6. 交互与命令

| 点 | 说明 |
|----|------|
| 操作抽象为 Command | `AddChild` / `AddSibling` / `Delete` / `SetText` / `ToggleCollapse` / `Move`… |
| Undo / Redo | 命令栈；macOS 惯例 ⌘Z / ⇧⌘Z |
| 命中测试 | 屏幕点 → 乘相机逆变换 → 与节点 AABB 求交 |
| 选中 | v1 **单选**；单击节点选中，点空白取消 |
| 编辑 | **双击**进入；浮层输入，**不做 Metal IME** |
| 快捷键（与原型对齐） | Tab 子主题、Enter 同级、⌫ 删除（非根） |
| 工具条 | 随选中态启用/禁用（根不可删、不可加同级等） |

## 7. 产品形态相关的技术约束

| 点 | 说明 |
|----|------|
| 单窗口 | `WindowGroup` 一个主界面即可；先不引入 `DocumentGroup` |
| 头脑风暴 vs 交付 | 同一 Model，不同投影（布局/主题/导出）；v1 只做前者核心 |
| 持久化 | 自有格式；与 XMind 专有格式不兼容（PRD 假设） |
| 性能预期 | 先定性：约百节点级平移缩放可交互，再定量帧率 |

## 8. HTML 原型已验证的技术点

路径：`prototype/`（DOM 节点 + SVG 连线，逻辑可迁移）。

| 已验证 | 对应能力 |
|--------|----------|
| 树 Model + side | 数据结构 |
| 中心辐射 Layout | 布局算法 |
| 相机平移/缩放/适应 | 导航 |
| 点选、双击编辑、增删折叠 | 交互 |
| 工具条状态机 | UI 壳与 Model 同步 |

**原生阶段注意：** 原型用 DOM/SVG；Mac 版用 Metal + 浮层编辑，但 **Model / Layout / 命令语义应保持一致**。
