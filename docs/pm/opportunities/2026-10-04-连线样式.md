# 机会卡片：Node 连线样式——曲线 / 大括号 / 正交折线

**课题：** YMind 父-子结构连线支持可切换样式（当前为正交折线），v1 支持 **曲线 + 大括号 + 正交折线**，全局一种、一键切换
**日期：** 2026-10-04
**状态：** 机会卡片（= 需求文档）；决策：**做**（见 §6 ICE）
**关联：** 调研记录 `research/2026-10-04-连线样式.md`

**人物：** 阿哲，独立开发者 / 知识工作者，用 YMind 做头脑风暴、方案拆解、读书笔记、知识体系整理。
**要完成的工作（JTBD）：**
- 让导图**看起来更精致、更专业**——像成熟竞品（XMind / MindNode）那样有顺滑的曲线连接，而非生硬折线。
- 用连线形态**辅助读图**——曲线更顺滑易读，大括号（`}`）直观表达「总分 / 从属」关系，帮读者一眼看懂结构语义。
- **无损地切换观感**：整图连线样式一键切换，不动数据、不动选中/折叠/相机。

## 2. 现状痛点

内部 `[ASSUMPTION]`（源码事实 + 产品访谈）：
- YMind 父-子连线**当前是 3 段正交折线**（横出→竖落→横进），不是曲线也不是直线（`RadialLayout.edge()` / `LogicLayout` → `EdgeGeometry.points`，`MetalRenderer.edgeVertices` 逐段直线描边）。
- 层级深、分支密时，正交折线**视觉生硬**、不易一眼辨层级从属；观感落后于竞品成熟度基线。
- 无任何连线样式选项——用户想换曲线/大括号只能羡慕竞品。

外部 `[EVIDENCE]`：
- **连线样式是导图工具成熟度基线**：MindNode「Rounded / Angular」分支类型（[mindnode.com/styling](https://www.mindnode.com/support/guides/mind-map-and-canvas-styling)）；Miro「curved / straight」（[help.miro.com](https://help.miro.com/hc/en-us/articles/360017730753-Mind-map)）；SimpleMind「curved / straight / rounded / angled」（[simplemind.eu](https://simplemind.eu/faq/relation-path)）；MindNoodle「Bezier / Orthogonal / Straight」（[github.com/MindNoodle](https://github.com/anpinghuang/MindNoodle)）。
- **大括号连线** = XMind 官方「括号图」结构（`}` 形），强表达总分从属（[xmind.app/features](https://xmind.app/features)）。
- **曲线 vs 折线是竞品最常见二分**，且几乎全部是**全局一种**作用域（MindNode 除外）。

## 3. 方案方向

**给父-子结构连线加一个可切换的全局样式，工具栏/菜单一键切换，整图即时重绘、无损。**

- **样式模型**：新增 `EdgeStyle` 枚举（`elbow` 正交折线[默认] / `curve` 曲线 / `brace` 大括号）。作用域 = 全局一种；**随文档持久化（`.ymind` 字段）、切换入命令栈（⌘Z 可撤销）**——产品本人拍板（原「会话态、不持久化」决策已推翻）。
- **Layout**：`EdgeGeometry` 扩 `style` + 曲线控制点字段（当前只有 `points` 折线点）。`RadialLayout` / `LogicLayout` **读 `document.edgeStyle`** 产出对应几何：
  - `elbow`：沿用现状 3 段折线。
  - `curve`：父→子发**贝塞尔控制点**（水平边垂直隆起避免退化直线；垂直边轴向平滑）。
  - `brace`：根→主分支 `}`、主分支→子 `∪`（XMind 括号图形态的轻量版，不动布局）。
- **持久化**：`MindMapDocument` 增 `edgeStyle` 字段（缺省 `.elbow`），Codec 升版本迁移（老文件缺省容错）；`currentVersion` 与布局 PRD 协调不撞（见 PRD §9.4）。
- **接缝**：样式是文档字段，`LayoutPipeline` / `LayoutEngine` / `PNGExporter` **签名不变**（都已传 `document`），引擎读 `document.edgeStyle`。**Render 只消费 `LayoutSnapshot`**，不读树（架构已验证）。
- **Render**：`MetalRenderer.edgeVertices` 对曲线**细分采样**成密集点喂现有逐段描边管线（曲线 → 细分直线段近似，无需新 shader，Metal 改动最小）；大括号走 Layout 细分的折线、正交折线走原逻辑。
- **切换器**：工具栏加「连线样式」菜单（仿布局切换器），切换走 `setEdgeStyle` 命令 → `relayout()`；选中/折叠/相机保持不变。

## 4. 范围（做什么）

- **FR-E1 样式模型与持久化**：`EdgeStyle` 枚举 + `MindMapDocument.edgeStyle` 字段（缺省 `elbow`）+ Codec 升版本迁移（老文件缺省容错，版本号与布局 PRD 协调）+ 切换入命令栈。可单测（枚举/默认值/迁移/命令往返）。
- **FR-E2 Layout 产样式几何**：`EdgeGeometry` 扩 `style` + 控制点；`RadialLayout` / `LogicLayout` **读 `document.edgeStyle`** 按样式产出折线/曲线/大括号几何（LayoutEngine/Pipeline 签名不变）。可单测（三种样式下各边几何/控制点）。
- **FR-E3 Render 曲线细分描边**：`MetalRenderer` 对曲线/大括号细分采样后复用现有描边管线；正交折线不变。可单测或冒烟（三种样式顶点输出）。
- **FR-E4 切换器**：工具栏「连线样式」菜单（或快捷键循环），切换即重排；选中/折叠/相机无损。可冒烟（切换后快照与相机状态断言）。
- **FR-E5 导出一致**：`PNGExporter` 按当前样式离屏渲染，导出图与屏幕一致。可冒烟（导出像素与屏幕同样式）。

## 5. 证据与假设清单

| 类型 | 条目 |
|------|------|
| `[EVIDENCE]` | 连线样式是竞品成熟度基线：MindNode Rounded/Angular、Miro curved/straight、SimpleMind 四种、MindNoodle Bezier/Orthogonal/Straight（来源见 §2） |
| `[EVIDENCE]` | 大括号 = XMind 官方「括号图」结构，强表达总分从属（[xmind.app/features](https://xmind.app/features)） |
| `[EVIDENCE]` | 竞品连线样式几乎都是**全局一种**作用域（MindNode 按主节点例外） |
| `[ASSUMPTION]` | 用户动机 = 视觉打磨 + 语义分层两者都要（产品本人访谈确认）；正交折线视觉生硬、曲线更顺滑专业 |
| `[ASSUMPTION]` | 样式**随文档持久化 + 入命令栈**（产品本人拍板，原「会话态、不持久化」决策推翻）；持久化成本 = Codec 版本迁移，路径与 `fill`/`layout` 同构（已走过两遍） |
| `[ASSUMPTION]` | 曲线可用 CPU 细分采样喂现有逐段描边管线实现，无需新 shader——Metal 改动最小 |
| `[ASSUMPTION]` | 大括号做成**全局连线样式**（非 XMind 式独立结构）成本可控，只动连线几何、不动布局 |

## 6. ICE 排序与决策

| 候选 | I | C | E | I×C/E | 决策 |
|------|---|---|---|-------|------|
| **连线样式（本卡）** | 7 | 8 | 7 | **8.0** | **做** |
| （对照）按分支/按节点设样式（E4） | 6 | 7 | 9 | 4.7 | 搁置（复杂，与全局作用域冲突） |
| （对照）连线动画 / 箭头端头 / 粗细 | 6 | 6 | 5 | 7.2 | 候选（后续按反馈排） |

**决策：做。** 理由：对齐竞品成熟度基线（主流全部支持、几乎全局一种，用户选择一致）；动机明确（视觉 + 语义两者都要，访谈确认）；架构友好（`edgeStyle` 是文档字段，引擎读 `document.edgeStyle` 签名不变，只扩 `EdgeGeometry` 样式字段 + Layout 产曲线控制点 + Render 细分，不动布局算法；持久化路径与 `fill`/`layout` 同构、成本可控）；工作量为中等（曲线最直接，大括号稍几何，持久化 + Codec 迁移小头）。

## 7. 排期建议

- **推荐：1.0（迁移闭环 + 节点图片）之后**，与「新增布局类型」串行或轻并行。理由：同在 Layout/Render 接缝动，避免与在开发中的图片/布局改动抢冲突；本课题独立、可随时插入。
- 待产品本人拍板具体排期。

## 8. 非目标（明确不做）

- 不做**按分支/按节点**分别设样式（E4 搁置，见 §6）。
- 不做**连线动画过渡**、**箭头/端头/粗细**、**线条颜色**（独立课题，后置）。
- 不做**联系线（Relationship）**（XMind 式任意两主题自定义连线，是独立元素，非父-子结构线，v1 不做）。
- 不做**曲线/大括号的布局结构调整**——只换连线几何，布局算法、节点排布不变。
