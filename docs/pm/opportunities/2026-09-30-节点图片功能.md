## 1. 人物 - 工作（P/J）

**人物：** 阿哲，独立开发者 / 知识工作者，用 Linva 做头脑风暴、方案拆解、读书笔记、设计整理。
**要完成的工作（JTBD）：**

## 2. 现状痛点

内部 `[ASSUMPTION]`：Linva 节点只有文字（`Node.text` + 填色）；想放图只能退出导图、把图放到别处、文字里写「见图 xx」——信息割裂。`[ASSUMPTION: 图片是当前最明显的表达能力缺口]`

外部 `[EVIDENCE]`：
- **图片是竞品官方标配核心能力**：XMind「Enrich a Topic」官方主打、6 种插入方式（含剪贴板粘贴/拖拽）；MindNode「Stickers, Emojis & Photos」官方 Core Feature。缺失即落后于成熟度基线（[xmind](https://xmind.com/user-guide/enrich-a-topic)、[mindnode](https://www.mindnode.com/support/guides/stickers-emojis-and-photos)）。
- **用户强诉求**：XMind 论坛用户抱怨粘贴插图体验（「唯一让我不订阅的点」）；AFFiNE/Trilium/Miro 社区都在要「类似 XMind 的节点插图」（[forum](https://support.xmind.net/hc/en-us/community/posts/900001902746)、[affine](https://community.affine.pro/c/feature-requests/image-insertion-in-mind-map-nodes)）。

## 3. 方案方向

**节点内嵌图片：粘贴 / 拖拽图片进节点，图 + 文共存显示，随文档持久化，随导出交付。**

- **数据**：`Node` 加 `image` 字段，**内嵌存储**（base64，文件自包含）；Codec 升 **v3** + 迁移（v2 无 image = 无图，天然容错——`fill` 先例）。
- **交互**：选中节点 → ⌘V 粘贴剪贴板图片 / 拖入图片文件 → 节点显示图；再次粘贴或菜单替换；⌫ 或右键清除图片。
- **显示**：图片 + 文字同框——布局尺寸 = 文字与图片合成（宽取 max、高叠加）；显示宽度设上限（参照 MindNode clamp 约 300px），点击可看原图（可后置）。
- **导出**：PNG（Metal 自动含图）✅；PDF 画图（随迁移闭环）；Markdown 降级（忽略图片或输出引用）。
- **命令/Undo**：`setImage` / `clearImage` 入命令栈（仿 `setFill`）。

## 4. 范围（做什么）

- **FR-G1 图片存储与编解码**：`Node.image`（内嵌 Data，编码上限压缩到 ≤1024px / 限定大小）；Codec v3 + v2→v3 迁移；`sanitize` 不变。可单测。
- **FR-G2 粘贴 / 拖入图片**：选中节点，⌘V 粘贴剪贴板图片（NSPasteboard 图片类型），或拖入图片文件（文件类型白名单：png/jpeg/gif/tiff/heic→转 png）；失败给可读提示；图片替换/清除（菜单或快捷键）。
- **FR-G3 图文同框布局**：`NodeFrame` 携带图片信息（尺寸/纹理引用）；`NodeSize` = max(文字宽, 图宽+边距) × (文字高+图高)；折叠/命中/选中不受影响。可单测（布局）。
- **FR-G4 图片渲染**：复用文字纹理管线——图片 → MTLTexture → quad 采样；Retina 对齐；缓存按脏键（图变才重建）；显示宽度 clamp（上限值实现时定，默认 ≤300pt）。
- **FR-G5 导出**：PNG 含图（Metal 自动）；PDF 画图（随迁移闭环 FR-E1 落地）；MD 输出图片说明引用或忽略（实现时定，默认忽略）。
- **FR-G6 分层与兼容**：`check-boundaries.sh` 白名单不变（AppKit/CoreGraphics/Metal 已就位）；命令栈一步 Undo；剪贴板复制节点自动带图。

## 5. 证据与假设清单

| 类型 | 条目 |
|------|------|
| `[EVIDENCE]` | 图片是 XMind/MindNode 官方核心能力，多方式插入（[xmind](https://xmind.com/user-guide/enrich-a-topic)、[mindnode](https://www.mindnode.com/support/guides/stickers-emojis-and-photos)） |
| `[EVIDENCE]` | 用户对 node/note 内嵌图强诉求、缺失即抱怨（[Xmind forum](https://support.xmind.net/hc/en-us/community/posts/900001902746)）；AFFiNE/Miro/Trilium 社区在要 |

| `[ASSUMPTION]` | 目标用户有「截图/参考图贴进导图」刚需场景（设计参考、读书笔记、方案素材） |
| `[ASSUMPTION]` | 内嵌 base64 + 尺寸上限优于外链文件（文件自包含、复制/移动不丢链；成本是文件变大，可接受） |
| `[ASSUMPTION]` | 图片渲染复用现有文字纹理管线（CGImage → MTLTexture → quad），无需新 shader 架构 |

## 6. ICE 排序与决策

| 候选 | I | C | E | I×C/E | 决策 |
|------|---|---|---|-------|------|
| **图片节点（本卡）** | 9 | 9 | 7 | **11.6** | **做**（排期见 §7） |

**决策：做。** 理由：竞品成熟度基线 + 用户刚需场景明确；架构友好（`fill` 先例、Codec 迁移路径已走过、渲染复用文字纹理管线）；成本中-高但可控，是「文字之外表达力」的第一块拼图。

## 7. 排期决策点（需产品本人拍板）

- **A. 进 1.0**：与迁移闭环并行开发（两者同动 Layout/Render，需协调避免冲突；1.0 上线即带图，竞品对比不落后）。成本：拖长 1.0 周期。
- **B. 1.1 首更**：1.0 先上无图版（纯文字合法，审核不拒），图片随 1.1 发布。成本：1.0 竞品对比暂时落后。
- 推荐 **B**（务实：迁移闭环已在开发、1.0 目标是尽快验证；图片功能需求包先就绪，1.0 提交前若排期允许可并批）。

## 8. 非目标（明确不做）

- 不做图片 URL/网络图（纯本地文件与剪贴板）；不做多图/相册管理、不做图片标注/裁剪编辑（压缩上限除外）。
- 不做视频 / 音频 / 附件文件（附件功能 v1.1+ 另行评估）。
- 不做 Markdown 图片导入（与迁移闭环 FR-I1 边界：导入 MD 含图 = 后续）。
- 图片不做自由缩放拖拽（固定显示上限，点击看原图后置）。
