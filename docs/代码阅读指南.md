# YMind 代码阅读指南（人工审读用）

**用途：** 代码是 AI 写的，你想自己看懂并人工把关。本文给你一条**按主链路推进、从整体到局部**的阅读路径，读完能独立回答「一条指令从按键到像素走了一遍什么」。每个章节都标注了「先看哪个文件 / 看什么 / 关键陷阱」。

**阅读前置：** 通读 `docs/架构现状.md`（尤其 §3 架构图、§4 数据流、§6 契约）。那份文档与代码同步维护，是地图；本文是「怎么走进地图」。

**核心心智模型（反复回来对照）：**

```
用户操作（菜单/快捷键/画布手势）
   │  经 DocumentSession 门面
   ▼
CommandBus（可逆命令栈，改树唯一入口）
   ▼
MindMapModel（纯数据树，无 UI）
   ▼
RadialLayout + TextMeasure（CPU 算几何）
   ▼
LayoutSnapshot（只读快照，Metal 唯一输入）
   ▼
MetalRenderer / TextAtlas / ImageTextureCache（GPU 画像素）
```

**三条铁律（审读任何改动都要检查是否被破坏）：**
1. **改树必走 `commandBus.execute(...)`**，否则 Undo 失真。相机/选中/搜索态不入栈。
2. **Render 只消费 `LayoutSnapshot`，不懂树**。凡 Render 里出现「读 Model / 读父子关系」就是红线。
3. **改 `.ymind` schema 必须递增 `currentVersion` 并写迁移**，否则老文件打不开。

---

## 0. 建议的总体阅读顺序

按依赖方向由外向内、再由内向外回推，每层约 30–60 分钟：

1. **入口壳**（App/ContentView）——看操作从哪来、挂到哪。
2. **内核**（Model → Commands）——看懂数据长什么样、怎么变。
3. **布局**（Layout）——看懂几何怎么算出来。
4. **渲染**（Render）——看懂像素怎么画出来。
5. **回读**（从 Render 逆着找每个输入是谁提供的）——确认分层没破。

下面按层拆解。

---

## 1. 入口壳：操作从哪来

**先看：**
- `YMindAppApp.swift`（菜单、打开/保存/导出、`DocumentWorkflow`、窗口态桥接）
- `ContentView.swift`（主视图、工具条、快捷键、把操作交给 Session）
- `App/NodeEditorOverlay.swift`（编辑浮层）

**看什么：**
- 一条用户操作（如「新建子节点」）最终调用的是哪个 `session.xxx(...)` 方法。
- 快捷键与菜单项是否都收敛到 Session / CommandBus，而不是散落各 View 直接改树。

**关键陷阱：**
- 编辑态的 ⌘V 粘贴图片：`CommitTextView.paste(_:)` 拦截 png/tiff → 回调 `onPasteImage` → 先 commit 文字再 `appendImageBlock`。不要只看普通 `paste:` 文本路径。
- `startEditing` 有一个 `guard snapshot.frames[id] != nil`：**未经布局的新节点（直接 `model.insertChild` 绕过布局）没有 frame，编辑会静默不启动**。这是删空删除节点测试踩过的坑。

---

## 2. 内核：数据与命令

### 2.1 数据模型（Model）

**先看：**
- `Model/Node.swift`（`ContentBlock`、`BlockImage`、`Node`）
- `Model/MindMapModel.swift`（`MindMapDocument`、树操作）
- `Model/YMindCodec.swift`（序列化 + 版本迁移）

**看什么：**
- `Node` 的**存储字段**是 `blocks: [ContentBlock]`；`text` / `image` / `imagePixelSize` 是**只读计算属性**。审读时注意区分「谁写存储」vs「谁读计算属性」。
- 命令栈的 Undo 基线取的是哪一份数据（编辑用 `originalBlocks` 作基线）。

**关键陷阱：**
- `currentVersion == 4`。任何改 schema 的提交必须：升版本 + 写迁移 + 老文件可解码（fallback 合成块）。
- `side` 只存根下一层，深层节点带 `side` 会被 `sanitize` 强制清掉。
- `Node` 是**值类型**（struct），「索引路径定位 + 追加」要避免整树拷贝。

### 2.2 命令栈（Commands）

**先看：**
- `Commands/CommandBus.swift`（`execute`、`undo`、`redo`、`applyDelete`）
- `Commands/MindMapCommand.swift`（15 个命令的定义）

**看什么：**
- `applyDelete` 的三个要点：`topLevelDeletableIds`（保根）、`removeMany`、undo 的 `restoreChild`（恢复原下标）。
- 每个命令是否**精确还原**（redo 复用原 id，如 `appendImageBlock`）；是否 no-op 不入栈（如 `setBlocks` 按内容比较）。

**关键陷阱：**
- 删空文字删节点走的是 `applyDelete`（`nonRootPureTextNode_deleteAllText_deletesNode`），不是 `setBlocks`。
- 新命令必须同时写 undo + redo 分支，缺一个就是半个命令。

## 3. 布局：几何从哪来

**先看：**
- `Layout/TextMeasure.swift`（量字，`measure(for:isRoot:) -> BlockMeasure{size, blocks}`）
- `Layout/RadialLayout.swift`（中心辐射 → 各节点 frame + 边几何）
- `Layout/LayoutSnapshot.swift`（`NodeFrame` / `BlockLayoutFrame` / `EdgeGeometry` / `ImagePayload` / `imagePayloads`）
- `Layout/LayoutConstants.swift`（间距常量，如 `imageMaxDisplayWidth = 300`）

**看什么：**
- `NodeFrame.blocks: [BlockLayoutFrame]`（`blockId` + `text?`（nil=图片）+ 局部 rect）如何按块序叠加（文本累行高、图片等比累图高、块间 `imageTextGap`）。
- `imagePayloads` 的 key 是**块 id**（不是节点 id）——这是内容流 v4 的关键改造。

**关键陷阱：**
- Layout 层允许 import `AppKit/CoreGraphics/CoreText`（量字），但**不碰 Metal**。
- `snapshot.frames` 必须包含每个可编辑节点——否则 `startEditing` 的 guard 早退（见 §1）。

---

## 4. 渲染：像素怎么画

**先看：**
- `Render/CanvasMetalView.swift`（`CanvasMTKView`、`CanvasTool`、`CanvasPointerGesture`、`keyDown` 分派）
- `Render/MetalRenderer.swift`（最重文件；`draw(in:)` + 离屏 `renderImage` 共用 `encodeContent`）
- `Render/TextAtlas.swift`（文字纹理栅格化，按**块 id** 缓存 + `evictUnused`）
- `Render/ImageTextureCache.swift`（图片纹理缓存：视口剔除 / 降采样 / LRU 128MB）
- `Render/CanvasHitTesting.swift`（命中：`hitTestImageBlock` 返回 `(nodeId, blockId)`）

**看什么：**
- `encodeContent` 只吃 `LayoutSnapshot` + Camera + 选中态，**不含父子关系**——确认渲染层真的不懂树。
- 图片选中态 `selectedImageBlock: (nodeId, blockId)?` 是会话态，不入栈、不入 `.ymind`。
- 文字纹理的 `flipVertically` 行翻转**必须保留**，删了文字会颠倒/错位。

**关键陷阱：**
- `ImageTextureCache` 不用 `Data.hashValue`（实测只取前缀字节，等长 PNG 会全碰撞显示旧图），用 O(1) baseAddress 比对 + memoized FNV-1a。
- PNG 导出走 `renderImage`，与在线 `draw` 共用 `encodeContent`，只是空 `branchToggles`。

## 5. 会话层：所有状态的枢纽

**先看（最关键）：** `Session/DocumentSession.swift`（门面，600 行+）

集中承载：文件 URL / 脏标记 / 选中（`selectedIds: Set<UUID>`）/ 编辑草稿（`editingId` / `draftText`）/ 相机 / 画布工具 / 搜索 / 快照 / 自动保存 / 恢复 / 导入预览。

**建议重点精读的方法：**
- `startEditing(_:)` / `commitEditingIfNeeded()` / `cancelEditing()` —— 编辑提交与聚拢规则。
- 聚拢规则（§18 spec）：原首非空块是图片 → `[images] + [text]`（图上文下），否则 `[text] + [images]`（文上图下）。
- 空文字三分支：有图→只留图；非根纯文本→删除节点；根→补「未命名」。

**关键陷阱：**
- `DocumentSession` 职责偏多（外部已有拆 `EditingController` / `Persistence` / `LayoutPipeline` 的建议，见架构现状 §7.4）——审读时留意它是否「什么都管」。

---

## 6. 导出 / 导入（可后读）

- **Markdown**：`Model/MarkdownExporter.swift`（纯函数，先序忽略折叠，「兄弟组递归判定」标题层级；有图 → 文件夹包 `N/N.md + assets/<blockId>.png`）。
- **PNG**：`Render/PNGExporter.swift`（复制文档清折叠 → 重布局 → 离屏光栅化）。
- **导入**：`Model/DocumentImporter.swift` + `MarkdownImporter.swift` + `XMLImporters.swift`（注册表路由，纯函数 `parse(Data)`）。
- **沙盒陷阱**：有图导出必须 SavePanel 选**目录**（`user-selected.read-write` 只授权所选文件，创建 `assets/` 子目录会被拒）。

## 7. 拿到一段新代码时，怎么审（checklist）

按顺序自查，任何一项不过即退回：

- [ ] **改树是否走命令栈？**（`commandBus.execute`）— 保 Undo。
- [ ] **no-op 是否入栈？**（无变化不入栈）
- [ ] **改 schema 是否升 `currentVersion` + 写迁移？** 老文件能否打开。
- [ ] **Render 是否读了 Model / 父子关系？** — 必须只吃 `LayoutSnapshot`。
- [ ] **块 id 是否贯穿到底？**（ContentBlock.id → BlockLayoutFrame.blockId → imagePayloads key → 纹理缓存 key → selectedImageBlock → MarkdownImage.blockId）断一处就是 id 不匹配。
- [ ] **选中态 / 相机 / 搜索是否误入 `.ymind`？** — 应为会话态。
- [ ] **新增 import 是否在白名单？**（`check-boundaries.sh` 会红）— 白名单见架构现状 §5。
- [ ] **Undo 是否精确还原？**（redo 复用原 id，恢复原下标）
- [ ] **值类型是否整树拷贝？**（大节点要避免）
